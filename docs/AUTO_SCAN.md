# 자동 진단: scan

`scan`은 모델을 실제 실행해 수치를 계산합니다. 평가 자료와 모델을 최초에 준비해야 하지만, 정확도나 위험 항목을 반복해서 JSON에 기록할 필요는 없습니다.

## 명령

~~~text
preprocess-review scan [folder]
preprocess-review scan --before before.joblib --after after.joblib --data evaluation.csv --attacks attacks.csv
preprocess-review scan --python PATH_TO_PYTHON --format json --out diagnosis.json
preprocess-review scan --demo
~~~

폴더를 생략하면 현재 폴더를 사용합니다. 상대 입력 경로는 지정 폴더 기준, 보고서의 `--out`은 명령을 실행한 현재 폴더 기준입니다. 기본 파일명은 위 예시와 같습니다. `attacks.csv`는 존재할 때만 자동으로 읽습니다. 다른 모델·데이터를 임의로 탐색하지 않습니다.

`--python` 대신 `PREPROCESS_REVIEW_PYTHON` 환경 변수도 사용할 수 있습니다. 실행 제한 시간은 기본 120초이고 `--timeout-seconds`로 1~3600초를 지정할 수 있습니다.

## 정상 CSV

~~~csv
id,label,feature_a,feature_b
sample-1,0,-0.8,0
sample-2,1,0.9,0
~~~

UTF-8 CSV이며 한 행은 하나의 평가 표본입니다. ID는 유일해야 하고, 정답은 모델의 클래스와 일치해야 합니다. 문자열 클래스 이름의 숫자 모양(`01`과 `1` 등)은 서로 다른 이름으로 보존합니다. 앞뒤 공백이나 제어 문자를 가진 클래스 이름은 이 버전에서 지원하지 않습니다. 특성은 결측·무한값이 없는 숫자 열입니다. `--label`, `--id`로 정답·ID 열 이름을 바꿀 수 있습니다. 회귀, 다중 출력, 원시 이미지·텍스트 및 임의 모델 형식은 이 버전에서 지원하지 않습니다.

전처리를 포함한 두 Pipeline에 **같은 원본 특성**을 전달합니다. 전처리가 모델 외부의 함수나 소스에만 있으면 해당 경로를 Pipeline에 연결해 저장해야 합니다. 파일 해시가 같다고 전체 의존성이나 결정성이 같다고 판정하지 않습니다.

## 공격 CSV

~~~csv
id,clean_id,attack_target,feature_a,feature_b
attack-1,sample-1,1,-0.8,1
~~~

`clean_id`는 정상 CSV의 ID와 연결합니다. `attack_target`은 그 공격의 목표 클래스입니다. 특성 이름은 정상 데이터와 같아야 하며, 실행 시 정상 CSV의 특성 순서로 정렬합니다. 이 버전은 정상 ID 하나당 공격 행 하나를 지원합니다. 여러 공격 기법은 별도 파일·별도 실행으로 평가하세요. 공격을 자동으로 만들거나 그 유효성을 증명하는 기능은 없습니다.

표적 공격 성공률의 분모는 **정답이 목표 클래스와 다르고 변경 전 정상 예측이 맞았던 대응 공격 표본**입니다. 변경 전후는 동일한 분모를 사용합니다. 원래 목표 클래스인 행과 변경 전 정상 예측이 틀린 행은 제외하고 그 이유를 JSON에 기록합니다. 따라서 모든 비목표 클래스 표본을 분모로 삼은 다른 ASR과 그대로 비교하면 안 됩니다.

## 관측 비율과 검사 정책

정상 오류율, 정상 예측 변경률, baseline 정답→candidate 오답의 유해 회귀율(전체 표본 분모와 baseline 정답 조건부 분모를 구분), 개선율, 조건부 표적 공격 성공률, 새로 성공한 공격 비율을 계산합니다. 분모가 0이면 0% 대신 미측정으로 표시합니다.

| 수준 | 공개된 판정 규칙 |
| --- | --- |
| 높음 | 정상 표본의 새 오류 또는 준비된 표적 공격의 새 성공을 하나 이상 관측 |
| 중간 | 새 유해 회귀는 없지만 예측 변화 또는 기존 오류·공격 성공을 관측 |
| 판단 근거 부족 | 앞선 신호는 없고 정상 또는 유효 공격 표본이 각각 100개라는 최소 기준을 충족하지 못함 |
| 시험 범위 내 낮음 | 앞선 신호가 없고 두 표본 수 기준을 충족 |

정책 버전은 `demo-conservative-0.1`입니다. **100개는 연구용 구현의 명시적 설정이며 검정력, 운영 안전성, 산업 기준을 보장하는 숫자가 아닙니다.** 높음·중간이어도 별도 표본 충족 상태가 부족할 수 있습니다. 낮음은 주어진 시험에서 이상 신호가 없었다는 범위에 한정됩니다. 예측 변화에는 개선도 포함되므로 예측 변경률을 실패 확률로 읽으면 안 됩니다.

기본 출력의 %는 관측 빈도입니다. 표집 방식은 코드로 추측하지 않습니다. 사용자가 독립·동일분포 표집을 가정해 `--assume-iid`를 지정할 때만 각 이진 지표에 Wilson 95% 구간을 제공합니다. 0건 관측이라도 상한은 양수입니다. 같은 원본의 반복 공격이나 종속 사례에 이 가정을 무조건 적용하면 안 됩니다. 대응 전후의 두 구간을 빼서 변화량의 신뢰구간을 만들지 않습니다. [NIST Wilson 공식](https://www.itl.nist.gov/div898/handbook/prc/section2/prc241.htm)

여러 지표의 개별 95% 구간은 종합 95% 안전 보장이 아닙니다. 공격 표본의 성공률을 실제 운영 사고 발생 확률로 바꾸는 모델은 이 도구에 없습니다.

## 실행 환경과 제한

실제 평가는 각 경로를 주어진 자료에 한 번씩 실행합니다. 비결정적 모델의 변동이나 외부 상태를 통제하지 않으므로, 관측된 차이를 전처리 변경만의 인과 효과로 확정하지 않습니다. 반복 실행·결정성·외부 의존성 검증은 별도입니다.

joblib 로드는 Python 코드를 실행할 수 있으므로 신뢰하는 아티팩트만 지정하세요. 학습에 사용한 Python/패키지 환경을 유지하는 것이 원칙이며, scikit-learn 버전 불일치 경고는 오류로 처리합니다. 이 도구는 모델 코드의 격리 실행 환경을 제공하지 않습니다. [scikit-learn 모델 저장·환경 호환성 문서](https://scikit-learn.org/stable/model_persistence.html)

입력 파일의 지문은 실행 전후 비교하고 변경이 발견되면 중단합니다. 지문은 해당 바이트를 기록할 뿐 모델·데이터 출처의 신뢰성, 외부 의존성의 완전성, 평가셋 대표성을 입증하지 않습니다. Python 실행 환경·행 수·특성 순서·분모·정책 버전은 JSON 보고서에 남깁니다. 모델 실행기에는 네트워크 호출이나 외부 업로드 코드가 없지만 사용자가 로드하는 모델의 임의 동작까지 제어하지는 못합니다.

잘못된 입력·실행 실패는 종료 코드 1입니다. 유효한 진단은 기본 0이며, `--strict`를 붙이면 시험 범위 내 낮음 외에는 2입니다. 기존 `check --strict`의 규제 축 조건과 별개입니다. 어떤 0도 배포 승인이나 법적 재인증 면제가 아닙니다.

## 데모의 출처

`--demo`는 Node.js만으로 실행됩니다. 고정된 200개 합성 정상 입력과 100개 합성 공격 입력에서 같은 단순 분류 함수에 방어 전처리를 적용하거나 해제합니다. 모델 학습·논문 원실험 재현·사용자 모델 평가는 하지 않습니다. 합성 입력이므로 이 모드는 `--assume-iid`를 받지 않습니다.
