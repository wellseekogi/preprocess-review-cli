# 후속 검증을 위한 연구 프로토콜 초안

상태: **제안된 미래 연구 설계. 모집·사용자 실험·전문가 합의 연구를 수행했다는 보고가 아닙니다.**

이 문서는 체크리스트와 도구가 전처리 변경의 평가 근거 재사용 판단을 개선하는지 확인하기 위한 실행 계획입니다. 소프트웨어 동작 검사와 거버넌스 효과 검증을 구분합니다.

## 1. 연구 질문

- RQ1: 프레임워크를 사용하면 제한된 기술적 근거의 재사용 가능 여부를 더 정확히 구분하고 필요한 추가 근거를 찾을 수 있는가?
- RQ2: 동일한 규칙을 문서로 제공했을 때와 실행 가능한 도구로 제공했을 때, 검토 시간·누락·판단 일관성에 차이가 있는가?
- RQ3: 고정 시험 결과의 재사용과 법적 새 적합성 평가 검토를 구분하는가? 도구의 문서화 상태를 법적 승인으로 오해하지 않는가?
- RQ4: 불확실성과 근거 공백을 적절히 표시하는가? 보류 증가에 따른 검토 부담과 위험한 재사용 감소 사이에 어떤 관계가 있는가?

## 2. 사례 자료 만들기

사례는 변경 전후 시스템 설명, 평가 주장, 사용 목적, 기존 평가 문서, 변경 계획, 시험 기록, 지문과 그 생성 근거를 묶은 검토 패킷으로 구성합니다. 연구자는 참가자에게 보여 줄 정보와 참조 판단에 사용한 정보를 구분해 기록합니다.

다음 조건을 포함하되, 각 조건의 수를 기계적으로 같게 만들어 실제 현장 빈도라고 해석하지 않습니다.

| 사례 조건 | 확인하려는 판단 |
| --- | --- |
| 실제 고정 평가 입력과 조건이 유지되는 변경 | 범위를 한정한 근거 재사용 |
| 정상 예측은 비슷하지만 공격·회귀 입력에서 달라지는 변경 | 불충분한 대리 지표의 한계 |
| 정규화·리사이즈·결측값 처리에서 다른 영향 기전 | 원고의 단일 기전 밖으로의 확장 |
| 의존성 누락 또는 결정성 미확인 | 정보 부족을 안전으로 처리하지 않는지 |
| 일부 시험 실패와 나머지 시험 통과가 공존 | 반증을 평균이나 다른 성공으로 덮지 않는지 |
| 계획은 있으나 최초 평가와의 연결이 불명확 | 계획 존재를 자동 면제로 오해하는지 |
| 고정 평가 조건은 같지만 사용 목적·대상 집단이 달라짐 | 기술적 근거와 법적 맥락을 분리하는지 |
| 고위험 여부·출시 시점·최초 평가가 불명확 | 규제 결론 대신 필요한 맥락을 요청하는지 |
| 서로 모순되는 선언이나 부정확한 지문 | 입력 신뢰와 근거 검증의 한계를 인식하는지 |

자료는 `원고에서 재사용한 사례`, `추가로 실제 실행한 실험`, `공개 사례 재구성`, `합성 시나리오`로 구분합니다. 공개 사례는 인용과 재구성의 변경 사항을 남깁니다. 합성 사례는 실제 운영 사고나 실험 결과처럼 서술하지 않습니다.

원고의 5,940개 전환을 그대로 독립 표본 5,940개로 취급하지 않습니다. 같은 모델·분할·전처리 경로를 공유하는 상관 구조를 기록하고, 독립성의 단위를 연구 목적에 맞게 정의합니다. `mask_br` 제거에서 여러 오류가 나와도 여러 종류의 위험 기전이 검증되었다고 세지 않습니다.

## 3. 참조 판단과 정답의 한계

### 기술적 판단

고정 평가의 재사용 여부를 비교하려면 새 경로에 같은 평가를 실제로 실행해 통과·실패를 얻습니다. 참조 결과는 그 평가의 범위에 한정됩니다. 알 수 없는 공격이나 실제 서비스 전체의 안전성을 참조 정답으로 삼지 않습니다.

지문 기반 판단의 참조 자료에는 실제 평가 아티팩트, 직렬화 규칙, 의존성 명세, 실행 조건과 재현 기록을 포함합니다. 실험에서 이들을 독립적으로 확인하지 않았다면 참가자의 오류와 자료 자체의 불완전성을 구분해 보고합니다.

### 규제 검토

ML 평가·보안과 법률·거버넌스 경험을 가진 검토자가 사례를 독립적으로 검토하고, 근거·불확실성·추가로 필요한 사실을 기록합니다. 합의 과정 전의 판단을 보존하여 불일치 자체를 분석합니다.

전문가 합의는 **연구상의 참조 판단**이며 법원의 판단이나 법적 정답이 아닙니다. 합의되지 않는 사례는 억지로 이진 정답으로 만들지 말고 쟁점과 합리적인 판단 범위를 기록합니다. 적용 법령의 판본과 검토 날짜도 사례마다 고정합니다.

## 4. 비교 조건

사람의 검토 실험에서는 다음 조건을 비교합니다.

| 조건 | 제공 자료 | 비교 목적 |
| --- | --- | --- |
| A. 기본 검토 | 동일 사례 자료와 동일 법 조항 발췌, 구조화되지 않은 기록 양식 | 통상적인 자료 검토와의 비교 |
| B. 문서 프레임워크 | A의 자료에 분류체계·체크리스트·판단 기준을 추가 | 프레임워크 자체의 효과 |
| C. 실행 도구 | B와 동일한 개념·기준을 도구로 제공하고 이유·공백·추적을 표시 | 구현과 표시 방식의 추가 효과 |

조건 간에 제공하는 실질적인 사실이나 법적 정보를 다르게 하지 않습니다. 차이가 생기면 이를 별도의 조작으로 명시합니다. 도구만 추가 정보를 제공하면 인터페이스 효과와 정보량 효과를 분리하기 어렵습니다.

참가자의 보안·ML·법적 검토 경험을 기록하고 배정에 반영합니다. 동일 참가자가 여러 조건을 수행하면 조건 순서를 무작위화하거나 균형 배정하며, 같은 사례의 답을 기억하는 효과를 줄이기 위해 사전 점검한 대응 사례를 사용합니다. 조건 간 학습·누출 가능성이 크면 참가자 간 설계를 고려합니다.

원고의 모델 동일성 M, 정상 예측 일치 C, 전면 재평가 F 같은 규칙은 **기술적 고정 평가 비교군**으로 별도 사용할 수 있습니다. 이 간이 규칙을 법적 판단 비교군이나 실제 MLOps 제품의 대표 동작으로 제시하지 않습니다.

## 5. 측정값과 분모

최종 상태만 비교하지 않고 판단 근거와 필요한 추가 조치를 함께 평가합니다.

| 측정 | 정의 또는 기록 방법 |
| --- | --- |
| 위험한 재사용 | 새 고정 평가가 실패하는 사례에서 이전 통과 결과를 재사용한 판단 |
| 전체 사례 중 위험한 재사용 | 위험한 재사용 수 / 판정 가능한 전체 기술 사례 수 |
| 재사용 중 위험한 재사용 | 위험한 재사용 수 / 재사용으로 판단한 기술 사례 수 |
| 실패 사례의 누락 | 위험한 재사용 수 / 새 고정 평가 실패 사례 수 |
| 불필요한 추가 검토 | 참조 근거가 제한적 재사용을 충분히 뒷받침하는 사례에서 요구한 추가 검토. 과도함의 기준과 논쟁 사례를 별도 기록 |
| 근거 공백 발견 | 사전에 정의한 필수 근거의 누락 중 참가자가 찾은 항목, 잘못 지적한 항목 |
| 규제 축의 적절한 분리 | 기술적 재시험과 법적 새 평가를 동일시했는지, 문서화 상태를 승인으로 오해했는지 |
| 검토자 간 일치 | 상태와 핵심 조치별 일치도. 결측·보류를 포함하고 범주 불균형을 함께 보고 |
| 검토 시간·부담 | 시작부터 제출까지의 활성 검토 시간, 중단 시간, 수정 횟수, 자가 보고 부담 |
| 판단 확신과 오류 | 참가자 확신도와 실제 오류의 관계, 도구 결과를 무비판적으로 수용한 사례 |

분모가 0인 비율은 0% 대신 정의되지 않음으로 표시합니다. 규제 사례는 참조 합의의 강도에 따라 층화하고, 전문가 불일치를 참가자의 단순 오답으로 처리하지 않습니다. 현장 표본을 사용하지 않은 연구에서는 사례 집합의 오류율을 실제 운영 빈도로 일반화하지 않습니다.

## 6. 실행과 분석 계획

1. **사례 패킷 작성:** 출처와 아티팩트를 확정하고 참가자용 자료·참조 자료를 분리합니다. 도구 버전과 사례 파일 지문을 기록합니다.
2. **소규모 예비 점검:** 용어 이해, 과제 난이도, 소요 시간과 자료 누락을 확인합니다. 예비 점검을 효과 검증 결과로 합치지 않습니다.
3. **주 분석 사전 명시:** 주요 결과, 제외 기준, 사례 배정, 결측 처리, 분석 단위와 효과 추정 방법을 정합니다. 외부 사전등록을 했다면 실제 주소·시점만 기록합니다.
4. **표본 수 결정:** 의미 있다고 볼 최소 차이, 예비 자료의 변동성과 참가자·사례 내 상관, 원하는 추정 정밀도를 근거로 산정합니다. 임의의 숫자를 충분한 검정력의 근거로 제시하지 않습니다.
5. **독립 참조 검토:** 검토자별 근거와 초기 불일치를 보존한 후 합의·쟁점 기록을 만듭니다. 비교 조건을 알면 영향을 받을 수 있는 평가자는 가능한 범위에서 가립니다.
6. **비교 실험 수행:** 참가자의 결정뿐 아니라 이유, 근거 요청, 불확실성과 도구 사용 기록을 수집합니다. 사람을 대상으로 하는 연구의 동의·자료 처리 절차는 소속 기관의 적용 요건에 맞춥니다.
7. **분석:** 조건별 효과 크기와 불확실성 구간을 보고합니다. 참가자와 사례의 반복 관측을 고려한 모형 또는 적절한 군집 재표집을 사용하고, 방법 선택의 가정을 명시합니다.
8. **민감도 점검:** 합성 사례 제외, 원고 단일 기전 제외, 전문가 불일치 사례 분리, 보류를 다르게 처리했을 때 결론이 유지되는지 확인합니다. 사후 추가 분석은 사후라고 표시합니다.
9. **실패 사례 분석:** 위험한 재사용, 과도한 보류, 모순된 입력, 법적 승인 오해의 원인을 정성적으로 분석합니다. 그 결과로 규칙을 바꾸면 새 버전을 별도로 평가합니다.

## 7. 공개할 연구 산출물

- 사례 목록, 출처, 생성·선정 기준, 사실·가정·합성 부분의 구분.
- 실제 실행한 기술 실험의 코드·설정·아티팩트 명세와 재현 기록.
- 참가자용 지침, 각 비교 조건의 자료, 질문지와 평가 기준.
- 개인을 식별하지 않는 범위의 판단 자료, 전문가 불일치와 합의 절차.
- 분석 코드와 결과. 계획 변경·제외 사례·실패한 분석도 구분하여 기록.
- 사용한 도구·규칙·법령 판본, 알려진 한계와 적용되지 않는 범위.

현재 배포물은 체크리스트, 연구용 구현과 예시를 제공합니다. 이 문서의 연구를 수행했거나 프레임워크의 효과가 입증되었다고 주장하지 않습니다. 원고의 통제된 반례, 합성 동작 예시, 향후 사람 대상 비교 평가를 각각 별도의 근거 수준으로 유지해야 합니다.
